RAG 检索配置

这些参数是 RAG（检索增强生成）知识库系统 的核心检索配置，涵盖了从召回、排序到融合的完整检索链路。下面按模块逐一解释：

一、基础检索模式

参数 含义 使用建议
检索模式 选择检索方式：向量检索（语义）、BM25（关键词）、混合检索、图检索等 通用场景选「混合检索」；专业术语密集选「BM25」；需要语义理解选「向量」
最终返回 Chunk 数 经过所有流程后，实际返回给前端的文档片段数量 一般设为 5-10，过多会增加大模型上下文压力，过少可能遗漏信息

二、相似度过滤

参数 含义 使用建议
相似度阈值（0-1） 过滤掉相似度低于此值的结果，0 表示不过滤 向量检索建议 0.5-0.7；BM25 建议 0.3-0.5；设为 0 时保留所有结果

三、BM25 全文检索参数

参数 含义 使用建议
BM25 召回数量 BM25 检索时从全文中捞取的候选文档数 建议 50-100，值越大召回越全，但后续排序压力越大
BM25 稀疏项丢弃比例 丢弃得分过低的稀疏词项，加速检索 0.0 表示不丢弃（保证召回）；追求速度可设 0.1-0.3，但可能漏召回
BM25 权重 混合检索中，BM25 结果的融合权重（与向量权重之和通常为 1） 关键词敏感场景（如法律、医学）可提高至 0.5-0.6

四、向量检索参数

参数 含义 使用建议
向量检索权重 混合检索中，向量（语义）召回结果的融合权重 语义理解场景可提高至 0.7-0.8；与 BM25 权重互补，两者之和通常 = 1
召回数量 向量检索或混合检索后，保留进入重排序的候选数量 启用重排序时建议 50-100，给精排模型足够候选

五、图检索（知识图谱增强）

参数 含义 使用建议
启用图检索 是否基于知识图谱进行实体/关系扩散检索 知识结构化程度高（如百科、企业知识）时建议开启
图实体召回数量 从用户 Query 中识别并召回的相关实体数量 建议 10-20，影响图谱入口的丰富度
图三元组召回数量 从 Query 中召回的「实体-关系-实体」三元组数量 建议 10-20，决定图谱推理的细粒度
图检索最大节点数 2-hop 扩散子图最多读取的节点数，防止图谱过大 建议 5000-10000，根据图谱规模调整
图召回 Chunk 数 通过 PPR（个性化 PageRank）从图谱路径召回的文本块数 建议 10-20，与向量/BM25 结果互补
图检索融合权重 最终排序时，图检索结果的加权系数 1.0 表示图结果与文本结果同等权重；若图质量高可维持，否则降低
PPR 阻尼系数 控制 PageRank 随机跳转概率，0.85 是经典值 一般保持 0.85；增大更关注局部结构，减小更关注全局

六、重排序（精排）

参数 含义 使用建议
启用重排序 是否使用专门的精排模型（如 BGE-Reranker、Cohere Rerank）对召回结果二次排序 强烈建议开启，能显著提升相关性
重排序模型 选择具体的重排序模型 根据部署情况选择，如 bge-reranker-v2-m3、cohere-rerank-v3 等
重排序后返回给前端的文档数量 经精排模型排序后，实际展示/传给 LLM 的文档数 建议 5-10，通常 ≤ 最终返回 Chunk 数

七、参数联动关系

1用户 Query
2    │
3    ├──→ 向量检索 ──→ 召回 50 个候选 ──┐
4    │                                  ├──→ 融合排序 ──→ 重排序模型 ──→ 取 Top 10 ──→ 前端/LLM
5    ├──→ BM25 检索 ──→ 召回 50 个候选 ──┤    (权重 0.7 vs 0.3)
6    │
7    └──→ 图检索（如启用）──→ 召回 20 个 Chunk ──→ 融合（权重 1.0）
8              │
9              └── 实体召回 10 + 三元组召回 10 ──→ PPR 扩散（最大 10000 节点）

八、典型场景配置参考

场景 检索模式 向量权重 BM25 权重 相似度阈值 重排序 图检索
通用问答 混合检索 0.7 0.3 0.5 开 关
法律/医学文档 混合检索 0.4 0.6 0.6 开 开
产品说明书 BM25 - 1.0 0.4 开 关
企业内部知识库 混合+图检索 0.6 0.4 0.5 开 开
开放式语义搜索 向量检索 1.0 0 0.3 开 关

核心原则：召回阶段求「全」，排序阶段求「准」，过滤阶段求「净」。如果检索结果经常漏掉关键信息，优先调大召回数量和降低稀疏项丢弃比例；如果结果相关性差，优先调整重排序模型和相似度阈值。
